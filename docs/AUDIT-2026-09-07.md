## Verdict and scope

pycmp is an experimental graph ingestion and retrieval system with a partially implemented corpus release. It is not yet a validated unknown-file classifier. Several confirmed defects damage the graph representation, training positives, and coverage of the evaluation corpus. More training on the current artifacts would not resolve those defects.

The shared-encoder direction is worth pursuing, provided the graph and data contracts are repaired first. Similar embeddings currently establish neither equivalent behavior nor maliciousness. Equal output dimensions do not establish cross-lane alignment.

This audit covers all first-party Python modules, CLI paths, manifests, Docker configuration, dependencies, tests, legacy entry points, documentation, and the locally generated release inventory. It includes controlled probes of first-party code and read-only inspection of pinned repository trees. It does not execute third-party corpus code, complete the interrupted build, retrain models, or implement source fixes. Remote repository contents have not received an exhaustive file-by-file license/security review. Recommendations are an engineering assessment, not a measured accuracy claim.

Audited base commit: `03293a3` (`Extract labeled upstream fixtures`). Six tracked files already had unfinished curation changes and `codegraph/curation.py` was untracked. Findings about release curation refer to that working tree; a fresh checkout of HEAD alone does not contain those changes. The audit preserves that work.

## Confirmed correctness blockers

### G01 — P0: duplicate graph node IDs corrupt edges

In `ASTNormalizer._graph_for`, IDs use `len(ids)` where `ids` is keyed by AST object identity. CPython reuses operator/context objects. Revisiting these overwrites dictionary entries while appending new nodes, eventually assigning the same node ID to different occurrences. `graph_tensors` then maps duplicate IDs to the last position. Edge destinations no longer reliably refer to their intended nodes.

Controlled source `def f(x): a=x+1; b=x+2; return a+b` (written on separate lines) yielded 26 nodes but only 21 unique IDs. A deterministic sample of the first 100 sorted existing graph-view files contained 1,206 graphs, of which **1,184 had duplicate IDs**. This is a convenience sample, not a random estimate of corpus-wide prevalence.

Repair node identity and enforce graph invariants before rebuilding. Existing graphs and downstream checkpoints/indexes need invalidation. CPython documents singleton operator/context nodes in its [AST reference](https://docs.python.org/3/library/ast.html).

### G02 — P0: semantically different code can have identical model inputs

`graph_tensors` encodes coarse `node.kind`, edge kind, count of available facts, and whether attributes exist. It ignores `ast_type`, opcode, names, constant categories/values, and syntax attributes. There is no feature-identity mask or user-selectable common-feature projection.

`def f(x): return x+1` and `def f(x): return x-1` produced exactly equal node-type, availability, edge-index, and edge-type tensors. Their cosine similarity was 1.0 under one randomly initialized encoder. Since the tensors are identical, training cannot distinguish this pair under the current representation.

API attributes such as the member name in `obj.send` are not recorded by the normalizer at all. Attribute values that are recorded still do not reach the network. Security capability retrieval needs operation/API evidence, not merely call-shaped trees.

### G03 — P0: positive augmentation changes behavior

The local renamer changes `ast.Name` uses but not `ast.arg` declarations. Probe output:

```python
# Original
def f(x):
    return x

# Current renamed_view result
def f(x):
    return arg_0
```

The output parses, yet references an undeclared name. Nested scopes reset a shared mapping; positional-only, keyword-only, variadic arguments and captures are not handled. These are currently eligible semantic positives. Disable this augmentation until scope-aware transformation and binding checks exist.

### G04 — P1: incomplete semantic graph and inconsistent unit boundaries

`function_graphs` drops module-level executable statements whenever any function exists. Nested functions are both included in enclosing subtrees and emitted separately. Module fallback is still labeled `unit_kind="function"`. There is no file-to-function aggregation in the main workflow.

Def-use construction links every load to the last visited definition with a matching hash, without scope, order, branches, parameter bindings, or reaching definitions. Sequential child fields have no list position, so statement/argument order is incompletely represented. Locations are declared available but not stored. There is no source CFG, resolved call graph, or exception-flow analysis. These graphs are predominantly structural AST graphs, not complete semantic program graphs.

### G05 — P1: cross-lane alignment is largely unimplemented

Recovery emits `core:recovery_syntax`/`core:recovery_error` and `recovery_child`; bytecode emits mostly `core:operation` with `contains` and `control_next`. Source uses AST-field edges. The model ignores the attributes that could distinguish and align operations across those lanes. No paired source/bytecode corpus is produced by the release builder, and current semantic training excludes recovery/damaged views.

The bytecode worker links sequential instructions even across unconditional transfers, marks jump targets without source-to-target jump edges, and omits stack/data flow and exception edges. All nested code objects live in a single graph, unlike source function units. Foreign portable xdis objects become a two-node placeholder rather than decoded operations. The assumed xdis return shape and supported versions lack integration coverage. Use the version-aware APIs documented by [xdis](https://github.com/rocky/python-xdis), with explicit tested version limits.

## Corpus and extraction findings

### C01 — P0: selection patterns silently lose whole repositories

Python `fnmatch` is not recursive path globbing with zero-or-more directory semantics. The special-case implementation only fixes leading `**/`. `src/requests/**/*.py` does not match `src/requests/api.py`. Git sparse-checkout uses yet another pattern interpretation.

Read-only `git ls-tree` at pinned revisions and the builder's own matching function showed:

| Record | Tracked `.py` files | Selected paths matching current suffix/globs | Retained in report |
|---|---:|---:|---:|
| requests | 37 | 0 | 0 |
| black_source | 345 | 1 | 0 |
| pyflakes_fixtures | 23 | 0 | 0 |
| pycodestyle_fixtures | 59 | 0 | 0 |
| hypothesis | 465 | 0 | 0 |
| certify | 0 | 0 | 0 |

Hypothesis is also configured under obsolete `hypothesis-python/` paths while the pinned tree uses `hypothesis/`. Certify's zero Python contribution is expected and should be an explicit disposition. A matching-file count, retained-unit count, and zero-match gate are required for each selection.

### C02 — P0: split logic does not achieve the planned benchmark

`stratified_splits` calls itself 70/15/15 but cycles seven training, one validation, and two test assignments: 70/10/20 for a full cycle. Strata shorter than eight groups get no holdout at all. Explicit partitions are ignored in this path. Sparse combinations of role and tier send every fixture to training.

Outside that path, explicit-vs-auto group conflicts are not rejected; cross-manifest merging checks names only. Repository aliases and related forks can evade grouping. NetExec/CrackMapExec require lineage-aware treatment. Assignments must be validated after actual retention, not just on manifest records.

### C03 — P1: cap and deduplication do not match the release contract

The cap is per record and applies to entire files/snippets before function graphs are created, not to 250 function/source units per underlying repository. MyPy/Black can receive multiple caps; a single large module yields many graphs. Sampling does not enforce the CPU envelope.

The AST digest includes identifiers but omits comments/layout. It is structural normalization, not an exact-byte hash. Invalid input collapses all whitespace; differently indented invalid snippets hash equally in a probe. Within-record duplicates remain, function duplicates inside different files are not checked, and duplicate ownership is decided before sampling, so an owner's later cap can discard the only retained representative. No retained hash catalog or per-item exclusion ledger is written. Duplicate detection does not cover generated variants.

### C04 — P1: fixture labels are heuristic and incomplete

MyPy `[out]` diagnostics and auxiliary `[file]`/stub sections are discarded. A case with an explicit type error only in `[out]` is labeled `accepted`. No annotation cannot safely mean accepted. Regex section parsing and `.strip()` can alter the intended source.

Markdown extraction supports a narrow triple-backtick syntax; it loses headings/configuration, rule IDs, multi-file context, and snapshots. The updated Ruff record only selects Markdown, dropping standalone Python fixtures previously included. The updated MyPy record drops standalone `.pyi` selections. Black input and output receive separate artifact IDs; its pair roles do not become positive-pair identities consumed by training. CPython extraction misses simple expressions (`compile("1+2", ..., "eval")` emitted zero fixtures), assigned strings, and structured helpers; substring-based call matching can over-label invalidity and reuse IDs for multiple string arguments. LibCST embedded cases are not extracted.

`diagnostic_family` is assigned from extractor identity, not a verified upstream diagnostic. Default Python 3.4–3.14 bounds are not evidence of actual grammar coverage. Container suffixes `.test`/`.md` are stored where consumers need emitted `.py`/`.pyi` source kind. Pair IDs based on whole-source hash are neither unit correspondence nor a supported equivalence relation.

### C05 — P0: checkout replacement can delete user data

`_checkout` recursively deletes an existing destination when HEAD differs or cannot be read. Its comment assumes exclusive ownership, but callers can supply arbitrary checkout roots. Manifest names and paths are not confined; absolute or parent-relative names can escape a root. Existing same-HEAD checkouts can have dirty contents or different sparse selections. HEAD alone is not content verification.

Replace deletion with validated, owned cache directories and quarantine/preserved conflicts. Reject traversal and symlink escapes; verify origin, tree, dirty state and selected content. This is a source-level finding; no destructive probe was executed.

### C06 — P1: release publication and reuse are not reliable

Graph cache keys omit extractor, normalizer, transformer, runtime and schema implementation versions. Cached graphs are reused merely because the file exists; empty files can be accepted and truncated files fail. Lane inference on reuse uses a different AST parse configuration than ingestion. Writes and final catalogs are not atomic. No complete marker, content inventory, integrity gate, bounded per-file worker or durable resume journal exists. The release manifest contains `partition="auto"`, not the computed assignments.

A directory of partial graphs cannot be advertised as a release. Preserve the existing output for investigation, then rebuild in a new versioned directory after graph corrections.

## Training, evaluation and retrieval findings

### T01 — P0: contrastive objective and batching are defective

The self-similarity diagonal stays in each softmax denominator; every anchor competes against itself. Other positive views are treated as negatives in pairwise losses. Two identical positive vectors with no other examples produce loss `0.693147`, illustrating the self-competition term. Implement a tested multi-positive objective with self exclusion; [Supervised Contrastive Learning](https://arxiv.org/abs/2004.11362) is a relevant reference.

`_batches` advances by `size//2` groups but truncates expanded groups to `size`; a probe with 8 groups × 3 views returned only 16 of 24 views. Model initialization is not seeded; epoch, batch and seed inputs are insufficiently validated. An empty run writes a checkpoint before raising. Optimizer/resume state and complete preprocessing identity are absent. Old catalogs without `semantic_trainable` silently lose all training examples under the new filter.

### T02 — P0: metrics do not establish classification

Evaluation retrieves mechanical positives inside the same small held-out gallery. Source/AST-unparse views can be identical at model input, making this easy even without learning. No untrained, exact-hash, token, graph-feature or conventional classifier baseline is compared. No unrelated-family rejection, security capability ground truth, or false-positive operating point exists.

Diagnostic/tier slices rerun paired-view retrieval with a smaller gallery; they do not measure diagnostic-family prediction and cannot be compared directly with full-gallery difficulty. Source/recovery and bytecode tasks are absent. `limit` is ignored by the current evaluator; a hard-coded Recall@5 threshold controls `accepts`. It allocates a full similarity matrix and sorts every row. Confidence intervals, repeated seeds and project-macro metrics are absent.

### R01 — P0: inference does not classify files

`search_artifact` encodes `result.graphs[0]` only. A changed second function or omitted module behavior has no effect on the query. Project pooling exists but is neither trained nor used by the retrieval workflow. The hybrid pool takes globally strongest function matches, allowing a small shared fragment to dominate without matched coverage.

Search discards similarity scores. No class taxonomy, evidence aggregation, novelty threshold, confidence calibration, abstention, or coverage explanation exists. Repository identity/security tier cannot serve as maliciousness ground truth: library and scanner code appears in legitimate uses as well.

### R02 — P1: incompatible embeddings can silently share an index

Index records omit checkpoint/preprocessing fingerprints and most provenance labels. Dimension equality is the only checked compatibility property. Separate random encoders of the same dimension can populate one index. The `embed --checkpoint` path expects a bare state dictionary while `train` writes a wrapped checkpoint, so those CLI commands are incompatible.

FAISS uses `IndexFlatIP`, an exact index rebuilt per search, not persisted ANN. JSONL upserts are non-atomic; IDs depend on enumeration order and stale records can remain on rebuild. There are no robust finite-vector, query-shape, loaded-record or limit checks. Filters exist in the low-level index but are not exposed in the main search CLI and lack the indexed metadata needed for planned tasks.

## Operational, dependency and documentation gaps

- Docker defaults are useful: network disabled, read-only filesystem, nonroot user, dropped capabilities and resource limits. However, the whole input parent is mounted, `docker info` has no timeout, output is captured unbounded, and terminating the Docker client may leave a container running. Source parser paths lack equivalent isolation/size/depth limits. Tests exercise trusted bytecode and a mocked unavailable sandbox, not successful Docker isolation or foreign-version decoding.
- Worker base image and decoder dependencies are unpinned. Failure backlog fields hold magic bytes/tool names rather than actual bytecode/tool versions; timeout and unavailable-worker outcomes are not uniformly recorded.
- Observed local runtime: Python 3.14.6, Torch 2.14.0, tree-sitter 0.26.0, tree-sitter-python 0.25.0. NumPy, torch-geometric, FAISS, xdis and uncompyle6 are absent locally. Decoder absence on the host is not proof of absence in Docker. Parser versions differ from `requirements.txt` (0.23.2/0.23.4) and the vendored grammar vocabulary. Full requirements installation was not attempted.
- `vocab.json` belongs to one tree-sitter grammar version, not all Python specifications. Legacy feature builders do not consume it, and the shared encoder uses hash buckets instead. Pin grammar/runtime contracts separately.
- No CI workflow or Python packaging/lock configuration was found outside generated repositories/environment directories. Current tests do not validate graph uniqueness, transformation semantics, cache integrity, real fixture extraction coverage, full CLI compatibility, or classification quality.
- Manifest validation accepts any nonempty revision, not strictly immutable commit IDs. Research tiers allow unverified license strings; that is a policy label, not a license audit. Verify license evidence at pinned commits and treat unresolved redistribution status explicitly. The project itself lists its license as unspecified.
- README emphasizes the legacy pipeline; STATUS reports 13 tests versus 15 now. Terms such as semantic, masked, comparable, FAISS-backed and benchmark-ready overstate some current paths. The all-repository release remains uncommitted/incomplete. Historical results must retain their original conditions and be marked superseded after representation fixes.
